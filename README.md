# daradara

**だらだらすることを、ちゃんと選べるようにする。**

`daradara` は、休養・リカバリーそのものに集中した行動設計ツールの構想です。

生産性を上げるための休養アプリではなく、**人が「休む」という行動を選びやすくすること自体**を目的にします。

## 問題意識

仕事・勉強・創作などには、完了、成果、通知、数字、streak などの即時報酬があります。一方、休養の利益は遅れて現れやすく、何もしないことには達成感も可視化もほとんどありません。

そのため、疲れていても「もう少し何かする」を選びやすく、休養は後回しになりがちです。

`daradara` では、行動経済学・行動科学・ゲーミフィケーションの知見を参考に、**休養側の摩擦を下げ、休まない側に少しだけ摩擦を置く**設計を考えます。

## 初期アイデア

### Recovery Check-in

現在の状態を簡単に入力します。精密な診断ではなく、本人の主観を軽く扱う想定です。

例：
- 頭が疲れている
- 身体が疲れている
- 刺激に疲れている
- 眠い
- なんとなく休みたい

### Recovery Menu

選択肢を増やしすぎず、そのとき選びやすい休養候補を数個だけ提示します。

例：
- 20分横になる
- 10分散歩する
- 温かい飲み物を飲んで何もしない
- 本・映画・音楽など受動的なインプットに切り替える

### Recovery Session

休養中に新しいタスクを増やしません。

「休むためのアプリを操作し続ける」状態を避け、必要ならシンプルなタイマー程度にします。

### Thought Parking

休んでいる途中で思いついた用事・アイデアを、**実行せずに一行だけ退避**できる仕組み。

「忘れたくないから今やる」を減らし、未来の自分へ安全に渡せる状態をつくります。

### Recovery Garden

休養を「何もしなかった時間」ではなく、自分で休養を選択できた事実として穏やかに可視化する案。

ただし、連続記録を失う不安や競争を生む強いstreakは避けます。休めなかった日に庭が枯れるような罰も置きません。

### Recovery Map

利用記録がたまったら、「自分には何が休養として効きやすかったか」を本人向けに振り返れる仕組みも検討します。

医療診断や疲労度の疑似的な精密測定は行わず、あくまで本人の記録からつくる“自分の休み方の取扱説明書”を目指します。

## 行動設計の仮説

検討したい要素：

- present bias / 現在バイアス
- action bias / 何かしていたくなる傾向
- default effect / 休養をデフォルト選択にする
- choice overload / 選択肢を絞る
- implementation intention / 「思いついたら実行せずParkingする」
- commitment device / あらかじめ休む時間を決める
- friction design / 休養は簡単に、作業再開には小さな摩擦を
- ゲーミフィケーションによる休養の即時報酬化

これらは現時点では**設計仮説**であり、調査・試作を通じて検証します。

## プロダクト原則（暫定）

1. 休養を生産性の従属物にしない。
2. 休むための操作を増やしすぎない。
3. 休めなかった日を失敗扱いしない。
4. 数字で身体状態を分かったふりをしない。
5. 医療診断・治療の代替を目指さない。
6. 「何もしない」を正当な選択肢として扱う。

## 名前について

仮称は **daradara**。

日本語の「だらだら」が持つ脱力感をあえて前面に出し、効率化された“回復”ではなく、休んでよいという許可そのものをブランドにしたいと考えています。
