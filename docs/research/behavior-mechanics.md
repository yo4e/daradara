# 競合の行動設計メカニクス調査

> 調査日: 2026-09-01 JST
>
> 目的: ダラリカ / darareco の最小MVPをUIやレコメンド精度だけで磨く前に、周辺アプリが「ユーザーの行動をどの瞬間に、どんな仕掛けで変えているか」を確認する。
>
> 本文は競合の公式サイト・公式ヘルプ・App Store掲載を中心にした予備調査。製品仕様は変更され得るため、実装判断時には必要な項目を再確認する。

## 今回の問題意識

現在のMVPは次の流れを持つ。

> 疲れた → ダラリカを自分で開く → 状態を選ぶ → 休養候補を選ぶ → Session → Thought Parking → 振り返り

この流れは最小検証として成立する一方、**「休むためにアプリを開く」という最も難しい意思決定を、すでにユーザー自身に要求している**。

そのままUIや候補数だけを磨くと、Thought Parkingという特徴は残るものの、「疲労チェック付きの少し賢い休憩タイマー」に近づく危険がある。

競合から見るべきなのは機能の数ではなく、次の4点である。

1. **いつ介入するか**
2. **どう状態をほどくか**
3. **休む行為そのものに、どんな手触りを与えるか**
4. **中断しかけた人を、どう休養へ戻すか**

## 1. one sec — 行動の「境目」に介入する

one sec の中心は、ユーザーに別アプリを起動させることではない。対象アプリやWebサイトを開こうとした瞬間に Intervention を差し込み、自動的な行動をいったん止める。

公式ドキュメントでは、Intervention は対象アプリを開く前の小さなエクササイズとして説明され、標準の呼吸のほか、一定時間の黒画面、指で点を追う、端末を回す等の介入を選べる。Immediate / Delayed / Re-Intervention など、介入タイミング自体も設計対象になっている。

さらに Healthy Alternatives では、対象アプリへ進まず、運動、趣味、読書、連絡など別行動へ移る選択肢を Intervention 内に出せる。

### ダラリカへの示唆

最も重要な参考点。

ダラリカも「休もうと思った人が開くアプリ」だけでなく、将来的には、

> もう一つ仕事を始める / SNSを開く / 動画をもう一本見る

といった**行動の境目**に小さな介入を置けるかを検討する価値がある。

候補例:

> 続ける / 休む / 思いつきだけ預ける

ここで重要なのは、作業やSNSを禁止することではなく、無意識の継続を一度「選択」に戻すこと。

Sources:
- https://one-sec.app/faq/
- https://tutorials.one-sec.app/en/articles/3310978
- https://tutorials.one-sec.app/en/articles/3974530
- https://tutorials.one-sec.app/en/articles/3036226

## 2. How We Feel — 状態を言葉にできないところから始める

How We Feel は「正しい行動をレコメンドする」ことより、自分の感情を理解し、そこから対処法へつなぐことを中心にしている。

今回の確認範囲では、公式サイトは「自分の感情をよりよく理解し、strategiesを見つける」アプリとして位置づけている。

### ダラリカへの示唆

現在の Check-in は「頭が疲れている / 身体が疲れている / 刺激に疲れている…」というラベル選択だが、疲れている本人が最初から自分の状態を適切に分類できるとは限らない。

今後の検討では、単純な診断質問を増やすのではなく、例えば

- 刺激を増やしたい / 減らしたい
- 身体を動かしたい / 止めたい
- 一人になりたい / 人の気配がほしい

のような、**本人が答えやすい少数の軸から「何を休ませたいか」を一緒にほどく体験**を検討する。

医療的な疲労判定や精密スコア化には進まない。

Source:
- https://howwefeel.org/

## 3. Do Nothing. — 「何もしない現在」に手触りを作る

PONOSの Do Nothing. は、過刺激な日常から離れて「何もしない」時間を取ること自体をテーマにしている。App Store掲載では、Doing Nothing 中は他アプリを使わないという明快なルールを置いている。

### ダラリカへの示唆

休養の結果を数値化したり、Gardenを育てたりする以前に、**休んでいる最中そのものが一つの体験になるか**を考える必要がある。

ただし、罰・連続記録・強い達成報酬を導入するとダラリカの原則と衝突する。

「何もしない時間に、ごく軽いユーモアや世界観だけがある」程度の低圧な手触りは検討候補。

Source:
- https://apps.apple.com/us/app/do-nothing/id6443578960

## 4. Gentler Streak — 休養を「例外」ではなく正規状態にする

Gentler Streak の Activity Path は、運動量と回復のバランスを可視化し、状態によっては休養や軽い回復運動を推奨する。公式ドキュメントでは休養中などのActivity Statusも扱われている。

### ダラリカへの示唆

重要なのは「休むことにもポイントを与える」ことではなく、**システムの状態空間の中に『今日は休む』が最初から普通に存在する**こと。

ダラリカでも、休養をメニューの一候補として出すだけでなく、

> 今は休養モードである

という状態そのものを正規の状態として扱う設計を検討する。

Sources:
- https://docs.gentler.app/understanding-your-activity-path/what-is-the-activity-path
- https://docs.gentler.app/understanding-your-activity-path/interpret-the-activity-path

## 5. Finch — 行動の意味を別の対象へ変換する

Finch はセルフケアのGoalを完了するとペットがエネルギーを得てAdventureへ進む。Self-careを直接「自分のために頑張る」行為としてだけ扱わず、ペットとの関係へ変換している。

### ダラリカへの示唆

これは強い仕掛けだが、そのまま導入すると quests / streak / アイテム / 収集などの報酬経済へ膨らみやすい。

参考になるのは、**本人が苦手な行為に、別の意味を与える**という原理だけ。

「休む＝成果を出せなかった」ではなく、「今の自分を休ませることを選んだ」という意味づけを、説教臭くなく体験として返せるかを検討する。

Sources:
- https://help.finchcare.com/hc/en-us/articles/42149821015693-New-User-Guide
- https://help.finchcare.com/hc/en-us/articles/37780000231309-Exploring-the-Finch-Home-Page

## 6. 15minutesnothing — 「静かなタイマー＋記録」はすでに競争領域

2026年時点で App Store には `15minutesnothing` があり、一定時間を静かに過ごすことを中心にしたシンプルな休止アプリが存在する。

### ダラリカへの示唆

ダラリカが

- タイマー
- 簡単なメモ
- セッション履歴
- 静かなUI

の品質だけで勝負すると、すでにあるプロダクトパターンに近づく。

Thought Parkingは差別化候補だが、それだけでは中心メカニクスとして弱い可能性がある。

Source:
- https://apps.apple.com/jp/app/15minutesnothing/id6758890197

## 現時点の設計仮説

現行MVPを捨てる必要はない。むしろ、最小フローを作ったことで「足りないもの」が見えた。

次にUIを磨く前に、少なくとも次の4問を検討する。

### A. いつ介入するか

現在:

> 休もうと思った人がダラリカを開く

検討:

> 休まず別行動へ流れそうな境目で、休養への再選択を作れないか

### B. どう状態をほどくか

現在:

> 疲れの種類を一つ選ぶ

検討:

> 本人が最初から状態名を知っている前提をやめ、2〜3回の軽い選択で「何を休ませたいか」に近づけないか

### C. 休む行為に何の手触りを与えるか

現在:

> タイマーが動く

検討:

> 成果・点数・streakではない、ごく静かな体験上の変化や世界観を置けないか

### D. どう休養へ戻すか

現在:

> Thought Parkingに一行書いてSessionへ戻る

これは競合比較後も強い候補。

ただし「入力欄がある」ことではなく、**思いついた瞬間に他アプリや仕事へ移らず、安心して休みに戻れる仕組み**として再設計する。

## 次の判断

Draft PR #4 のプロトタイプは基準点として保持し、現時点ではUI磨きや機能追加を急がない。

次に検討する中心テーマ:

> ダラリカは「休み方を提案するアプリ」なのか、それとも「休まず次の行動へ流れる瞬間を、休む選択へ戻す装置」なのか。

後者を中心に置く場合、現行MVPのStart / Check-in / Menuの役割そのものを見直す可能性がある。
